# DVMA Branding

Single source of truth for the DVMA visual identity: the app icon, the launch
/ splash screen, and the design tokens they share.

## Design tokens

Colors, radii, and spacing live in `lib/core/theme/dvma_colors.dart`. The two
values the native launch surfaces reuse:

| Token | Hex | Use |
| --- | --- | --- |
| Dark base (`DvmaPalette.dark.base`) | `#0D1210` | splash background (both modes, DVMA is dark-first) |
| Light base (`DvmaPalette.light.base`) | `#F4F6F4` | light-mode splash background (provided for completeness) |
| Accent (`DvmaColors.accent`) | `#E8A33D` | hazard-amber brand mark |

## App icons

Generated by `flutter_launcher_icons` from `assets/branding/dvma_icon.png`
(+ adaptive foreground). Config: `config/flutter_launcher_icons.yaml`.

```sh
dart run flutter_launcher_icons -f config/flutter_launcher_icons.yaml
```

## Launch / splash screen

Generated by `flutter_native_splash` for Android (incl. the Android 12+
`SplashScreen` API) and iOS. Config: `config/flutter_native_splash.yaml`.

The raw brand foreground art carries a large transparent margin, so centering
it verbatim makes the mark look tiny. We therefore pre-process the art, trim the transparent bounding box, upscale the mark to ~62-66% of the canvas,
darken the phone body toward the base color (`PHONE_DARKEN_FACTOR`, so the
amber hazard mark is the clear hero), and composite on the brand base, before
handing it to the generator.

### Regenerate (two steps)

1. Build the processed splash source images (requires Pillow). The repo Python
   may be an externally-managed install, so use a throwaway venv:

   ```sh
   python3 -m venv .venv && .venv/bin/pip install --index-url https://pypi.org/simple Pillow
   .venv/bin/python tool/build_splash_assets.py
   rm -rf .venv
   ```

   This writes `assets/branding/splash/dvma_splash_{light,dark}.png` and the
   transparent Android-12 variants.

2. Generate the native splash for both platforms:

   ```sh
   dart run flutter_native_splash:create --path config/flutter_native_splash.yaml
   ```

### Version pin note

`flutter_native_splash` is pinned to **^2.4.7**: it compiles against Android
API 35 (required by AGP 9) and depends on `image` / `archive` 4.x, which matches
the repo's `archive ^4.0.0` pin. The `zip_path_traversal` module uses the same
`archive` 4.x API, so the splash tooling and the module resolve against one
shared `archive` major version with no conflicting bump.
